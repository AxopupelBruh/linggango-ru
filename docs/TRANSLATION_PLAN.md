### Ответ на вопрос про «1.2k токенов»

1.2k токенов не хватит: полный объём — 2.84 млн символов, это ~711k токенов только на вход
и столько же на вывод. Через один чат это не проходит по объёму ответа. Но есть рабочая схема:

* **Google Translate** делает массу (2.84 млн символов ≈ 1 900 запросов по 1 500 символов,
  при 4 потоках и задержке — 20–40 минут чистого времени);
* **я (MiniMax M3.1)** делаю то, что Google не умеет: глоссарий терминов, названия глав
  и квестов, починку строк, не прошедших валидацию, финальную вычитку;
* результат сходится в один кэш `translations.json` → реиспользуется при повторных прогонах.

## 2. Архитектура

```
LINGGANGO/
├── resourcepacks/
│   └── zz_linggango_ru.zip        ← НОВЫЙ: все lang-файлы модов + Patchouli-книги
├── config/ftbquests/quests/**     ← ИЗМЕНЯЕМ: расшифровать → перевести → зашифровать
├── kubejs/assets/<ns>/lang/ru_ru.json   ← НОВЫЕ
├── kubejs/client_scripts/lang.js  ← ИЗМЕНЯЕМ: добавить блок ru_ru
├── config/linggango-resourcepacks.toml  ← ИЗМЕНЯЕМ: наш пак последним = высший приоритет
└── .linggango-translate/          ← НОВЫЙ: весь инструментарий + бэкапы
    ├── lgq_crypt.py                расшифровка/шифрование LGQ1
    ├── extract_quests.py           сбор строк из квестов
    ├── translate.py                конвейер перевода (Google + кэш + глоссарий)
    ├── glossary.json               словарь терминов EN→RU
    ├── validate.py                 проверка плейсхолдеров и структуры
    ├── build_resourcepack.py       сборка ресурспака
    └── apply_quests.py             расшифровка→перевод→перешифровка квестов
```

**Почему ресурспак, а не правка jar:** сборка обновляется через CurseForge — jar-ы перезапишутся.
Ресурспак переживает обновление, его достаточно пересобрать. Jar-ы не трогаем вообще.

**Приоритет ресурспака:** пак сам управляет порядком через `config/linggango-resourcepacks.toml`
(«lowest priority first»). Наш пак добавляется **последним** записью `file/zz_linggango_ru.zip`,
чтобы его `ru_ru.json` перекрывали чужие.

## 3. Этапы работ

### Этап 0. Бэкап и страховка
1. `tar czf .linggango-translate/backup/quests_backup.tgz config/ftbquests/quests`
2. `tar czf .../kubejs_backup.tgz kubejs`
3. `tar czf .../resourcepacks_backup.tgz resourcepacks`
4. Отдельно сохранить **оригинальные** расшифрованные квесты в `.linggango-translate/plain/` —
   чтобы всегда можно было пересобрать зашифрованные из исходников.

### Этап 1. Словарь терминов (глоссарий) — делаю я
Собираю `glossary.json` из терминов, реально встречающихся в сборке:
* ванильные и модовые блоки/предметы (Deepslate, Netherite, Cursed, Ancient, Void, Arcane…);
* боссы и энемии (Warden, Sentry, Colossus, Archivist…);
* зачарования, руны, элементы (Fire/Cold/Thunder/Anima/Lapis), классы, таланты;
* механики сборки (AE2, Create, Mekanism, Ars Nouveau…).

Механика применения: термин → плейсхолдер `⟦7⟧` до перевода → восстановление после.
Это гарантирует единообразие: Google один раз переведёт «Warden» как «Смотритель», другой — как
«Страж»; глоссарий оставит везде «Страж».

### Этап 2. Конвейер перевода (Google + я)
* `translate.py`: батчинг по ~1 500 символов / до 40 строк, разделитель `\n` (проверено — не
  разъезжается), `requests` + retry/backoff на 429, 4 потока, кэш в `translations.json`;
* защита плейсхолдеров: `%s`, `%d`, `%.2f`, `%1$s`, `{0}`, `{}`, `§a`, `<tag>`, `item.id`,
  JSON-скобки — проверяются до/после, при несовпадении строка уходит в ручную очередь;
* отсев мусора: значения-идентификаторы (`minecraft:stone`, команды, ключи конфигов) не
  переводятся, а копируются как есть;
* **ручная очередь** — то, что не прошло валидацию или неоднозначно: перевожу я, здесь и в
  чате, порциями.

### Этап 3. Моды → ресурспак (самый заметный эффект)
1. Собрать по неймспейсам объединённые `en_us` + существующие `ru_ru` из 429 модов;
2. для каждого неймспейса взять **только недостающие** ключи (чужие хорошие переводы не
   трогаем);
3. перевести, записать `assets/<ns>/lang/ru_ru.json` в ресурспак;
4. `pack.mcmeta` с `pack_format: 15` (1.20.1) и описанием «Linggango RU»;
5. добавить `file/zz_linggango_ru.zip` последним в `config/linggango-resourcepacks.toml`
   и в `options.txt` → `resourcePacks`.

Затронутые неймспейсы: 245 модов, топ — `saintsdragons` (2 126), `goetyawaken` (1 671),
`simplyswords` (1 670), `linggango_tweaks` (1 352), `brutality` (1 203), `bloodmagic` (942),
`macabre` (941), `tiered` (868), `goety_revelation` (754), `hexerei` (698), `animus` (645).

### Этап 4. KubeJS
* `kubejs/assets/<ns>/lang/ru_ru.json` — 7 файлов, 1 031 ключ;
* `kubejs/client_scripts/lang.js` — сейчас только блок `en_us` с 64 `renameItem`;
  добавить блок `ClientEvents.lang("ru_ru", ...)` с теми же 64 предметами по-русски
  (в русской локали без него эти предметы показывают дефолтные/английские названия).

### Этап 5. Квесты FTB
1. `extract_quests.py` — вытащить все `title`/`subtitle`/`hover` из 186 файлов (уже сделано,
   9 569 уникальных строк);
2. перевести через общий конвейер;
3. `apply_quests.py` — для каждого файла: расшифровать → подставить переводы **только** в
   поля `title`/`subtitle`/`hover` → зашифровать обратно тем же ключом;
4. **не трогать** `id`, `icon`, `dependencies`, `rewards`, `images` — только текстовые поля;
5. проверка: расшифровать результат, распарсить, сравнить структуру (число квестов, id, зависимости)
   с исходником — должно совпасть 1:1.

> Мод при сохранении квестов сам перезашифрует файлы обратно — наш формат полностью совместим,
> поэтому всё работает штатно.

### Этап 6. Patchouli-книги
* 22 книги без `ru_ru` (ars_nouveau, BloodMagic guide, EnigmaticLegacy, Macabre, terramity
  и др.) — записи в `assets/<ns>/patchouli_books/<book>/ru_ru/entries/**.json`;
* 6 книг уже с `ru_ru` — оставляем как есть;
* **риск**: Patchouli грузит книги через ResourceManager, поэтому ресурспак должен работать —
  проверяется на одной книге первым делом; если нет — точечная перепаковка только этих 22 jar-ов
  (fallback, отдельным шагом и с бэкапом).

### Этап 7. Финальная вычитка (делаю я)
* заголовки 12 актов и названия глав — вручную, это первое, что бросается в глаза;
* ~500 самых заметных строк (названия предметов, подсказки, названия боссов) — вычитка;
* отчёт: что переведено, что оставлено на английском и почему.

## 4. Контроль качества

Автоматические проверки после каждого этапа:

| Проверка | Критерий |
|---|---|
| Плейсхолдеры | множество `{0}`, `%s`, `§a` до = после, 100% |
| Структура JSON | те же ключи, те же типы, ни один ключ не потерян |
| Структура snbt | то же число квестов/иконок/зависимостей, id не изменились |
| Round-trip шифрования | decrypt(encrypt(x)) == x для всех 186 файлов |
| Латиница | строки с >3 латинских букв без русского — в отчёт на вычитку |
| Пустые значения | перевод не может быть пустым |
| Неизменность | `id`/`icon`/`dependencies`/`rewards` побайтно совпадают с исходником |

## 5. Риски и что делать, если не сработает

| Риск | Решение |
|---|---|
| Google режет длинные строки | дробить на абзацы по `\n`; для описаний >4 000 символов — переводить по абзацам |
| Google ломает термины | глоссарий + ручная очередь |
| Google rate-limit (429) | backoff, 4 потока, кэш; при отказе — пауза 10–60 с |
| Ресурспак не подхватился | проверяется логом клиента; в `options.txt` пак указывается `file/...zip` |
| Patchouli не берёт `ru_ru` из ресурспака | fallback: перепаковка 22 jar-ов с бэкапом |
| Сборка обновилась и сбросила конфиги | всё лежит в `.linggango-translate/`, пересборка одной командой |
| Квесты не расшифровались после правки | `apply_quests.py` идемпотентен, можно перезапустить с нуля |

## Что чинилось по ходу

* **Описания квестов — это списки.** Раньше переводились только `title`/`subtitle`:
  4 655 блоков `description: [ "…" ]` оставались английскими. Парсер переписан (`snbt_text.py`),
  добавлены однострочные массивы и заголовки внутри строки — стало 44 629 текстовых поля.
* **Баг со смещениями в многострочных блоках** (описания) ломал файлы при подстановке.
  Исправлено, переводы переприменены с нуля из оригиналов.
* **Битые lang-файлы модов** (BOM, `//`-комментарии, висячие запятые, потерянные запятые) —
  3 мода (`shouldersurfing`, `tonsofenchants`, `cameraoverhaul_revamp`) целиком выпадали
  из перевода. Написан терпимый загрузчик (`lang_json.py`), пропуск устранён.
* **Названия черт** (Killer Aura, Ragnarok, Reflect, Adaptive…) в игре показываются
  по-английски — в тексте они тоже оставлены английскими, чтобы совпадать с экраном.
* **DeepL: лимит на аккаунт, а не на ключ.** Оба ключа `:fx` берут из одного пула в 500 000 символов,
  поэтому 456 приходит на обоих. У аккаунта есть Pro-план на 1 000 000 (израсходовано 517 180) —
  чтобы его использовать, нужен ключ **без суффикса `:fx`**.
* **Разметка квестов ломалась переводом:** `[gap=5]` → `[пробел=5]` (4 269 вхождений),
  `[!danger]` → `[!опасность]`, `{image:…}` → `…:текстуры/x.png` (128 битых ссылок →
  `ResourceLocationException`). Разметка вынесена в защищённую регулярку `RE_MARKUP`,
  написан `repair_markup.py` — восстановлено 1 092 маркера.

## Сверка с чужим переводом (k1n1maro/-Linggango)

Чужой перевод выложен открытым SNBT (наш — в шифре `LGQ1`), 48 глав совпадают.
Сопоставление — по id квеста внутри глав, строки внутри квеста выровнены по разметке
(`ftbq_parse.py`, `compare_github.py`): **1 823 строки с обоими вариантами**.

Что из этого вышло:

* **71 реальный дефект нашего перевода** (не 1 823 «различия»): сломанные термины
  («Source» → «исходные файлы», «Will» → «Демон Будет»), потерянные слова
  («Алтаря ,»), дубли («Кольцо семи семи проклятий»), неверный падеж
  («Усиленный грифельный»). Исправлено точечно — с сохранением разметки и ZWNJ-разбивки
  (`manual_github_merge.py`).
* **Их перевод берём не весь:** у них переведены ключи внутри `{image:…}`
  (`width:` → `ширина:`), из-за чего ломаются картинки; ZWNJ-разбивку они выкинули,
  поэтому текст в игре переносится иначе.
* **Сверили терминологию по всей сборке** (`audit_terms.py`): нашлись **141 термин,
  переведённый двумя способами** — «Скалк/Скулк», «Элитры/Надкрылья», «Раздатчик/Диспенсер»,
  «Твёрдость брони/Прочность брони», «Спрут/Кальмар», «Визер/Уизер/Иссушитель»,
  «буфф/шлифование», «сланец/грифельный/лист/доска» и т.д. Канон взят из официальной

## Разбор «Как  лидер железных» — маркеры ZWNJ (U+200C)

В квестах автор пака расставляет **невидимый маркер переноса** ZWNJ:

```
As<Z> the<Z> leader of<Z> the<Z> Iron Golems…   ← так в оригинале
Как<Z> лидер<Z> Железных<Z> големов…            ← так должно быть
```

Инварианты оригинала (проверено по всем 11 698 строкам EN):
ZWNJ никогда не стоит в начале строки, перед ним никогда нет пробела,
после него ровно один пробел, два ZWNJ подряд не встречаются.

Перевод (DeepL/Google) маркеры растащил: появились `ZWNJ + два пробела`,
`пробел + ZWNJ`, `ZWNJ ZWNJ` — в игре это и видно как лишние пробелы.

Что выяснено про сам маркер: **в коде FTB Quests и FTB Library U+200C не обрабатывается
вообще** (проверено поиском по байткоду всех 429 модов) — то есть он невидим и влияет
только на пробелы вокруг себя. Поэтому важны не точные позиции маркеров, а их количество
и отсутствие «рваных» пробелов.

Скрипт `fix_zwnj.py` пересобирает расстановку заново по образцу оригинала:
маркер ставится строго «слово + ZWNJ + один пробел», позиция подбирается
пропорционально позиции маркера в EN, маркеры не заходят внутрь разметки
(`<grad …>`, `{image:…}`, `[item:…]`, цвета, ID), лишние пробелы схлопываются.

Итог по всем 186 файлам квестов: 60 706 маркеров, **0** случаев «ZWNJ + два пробела»,
**0** «пробел перед ZWNJ», **0** «два ZWNJ подряд», **0** маркеров на краю строки.

## Как это можно повторить

Всё в `.linggango-translate/`:

```bash
cd .linggango-translate
./venv/bin/python collect.py                       # собрать строки
./venv/bin/python collect_extra.py                 # подсказки, меню, конфиги
./venv/bin/python build_glossary.py                # обновить глоссарий
./venv/bin/python run.py --source mods --backend google   # перевести
./venv/bin/python repair_markup.py                 # восстановить разметку квестов
./venv/bin/python manual_github_merge.py           # правки после сверки с чужим переводом
./venv/bin/python normalize_terms.py               # выровнять терминологию по всей сборке
./venv/bin/python audit_terms.py                   # найти оставшиеся расхождения терминов
./venv/bin/python polish_ru.py                     # пунктуация + единообразие «ё»
./venv/bin/python fix_zwnj.py                      # расстановка маркеров переноса ZWNJ
./venv/bin/python apply_manual_round4.py           # точечные правки (экран смерти, названия)
./venv/bin/python apply_quests.py                  # вшить перевод в квесты
./venv/bin/python apply_extra.py                   # вшить перевод в конфиги
./venv/bin/python apply_kubejs.py                  # вшить перевод в kubejs
./venv/bin/python build_resourcepack.py            # собрать ресурспак
./venv/bin/python verify.py                        # проверка
./venv/bin/python verify_quests.py                 # проверка квестов
```

Перед `apply_quests.py` оригиналы квестов надо восстановить (иначе перевод
не применится поверх уже переведённого файла):

```bash
./venv/bin/python - <<'PY'
import shutil
from pathlib import Path
HERE = Path("/home/ax/Documents/curseforge/minecraft/Instances/Linggango/.linggango-translate")
src = HERE / "backup/quests_original"; dst = HERE.parent / "config/ftbquests/quests"
for f in src.rglob("*.snbt"):
    t = dst / f.relative_to(src); t.parent.mkdir(parents=True, exist_ok=True); shutil.copy2(f, t)
print("оригиналы восстановлены")
PY
```

Ключи DeepL лежат в `.deepl_keys` (права 600). Кэш переводов — `cache_*.json`,
поэтому повторные запуски не тратят лимит.

**Бэкапы оригиналов:** `.linggango-translate/backup/` —
`quests_backup.tgz`, `kubejs_backup.tgz`, `resourcepacks_backup.tgz`,
`quests_original/` (расшифрованные оригиналы квестов),
`config_extra/` (оригиналы конфигов меню и подсказок).
